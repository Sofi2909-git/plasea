REQUERIMIENTOS FUNCIONALES

RF-01	E1 Acceso y cuentas	Usuario (todos los roles)	El sistema deberá permitir a un usuario con cuenta activa iniciar sesión con su correo y su contraseña.	Como usuario, quiero iniciar sesión con mi correo institucional y mi contraseña, para acceder a las funciones de mi rol.	Con credenciales válidas entra a la página de inicio de su rol. Con credenciales inválidas se muestra un mensaje genérico que no revela cuál dato falló. Una cuenta inactiva o bloqueada no inicia sesión.
RF-02	E1 Acceso y cuentas	Sistema	El sistema deberá permitir a cada usuario acceder únicamente a las funciones asignadas a su rol (Profesor, Auditor académico o Administrador del sistema) y rechazar el acceso directo a cualquier función no autorizada.	Como administrador del sistema, quiero que cada rol vea solo sus funciones, para proteger la información.	Se cumple la matriz de permisos de los 3 roles. Un profesor que abre por URL una función de administración recibe "acceso denegado" (HTTP 403). El menú solo muestra opciones permitidas.
RF-03	E1 Acceso y cuentas	Usuario (todos los roles)	El sistema deberá permitir al usuario cerrar su sesión activa.	Como usuario, quiero cerrar mi sesión, para evitar que otra persona use mi cuenta.	Tras cerrar sesión, el botón "atrás" del navegador no muestra datos protegidos y la sesión anterior no puede reutilizarse.
RF-04	E1 Acceso y cuentas	Sistema	El sistema deberá cerrar automáticamente la sesión de un usuario tras 30 minutos sin actividad.	Como usuario, quiero que mi sesión se cierre sola si me ausento, para evitar accesos indebidos.	Pasados 30 minutos sin actividad, la siguiente acción redirige al inicio de sesión. El tiempo es un parámetro del archivo de configuración (por defecto 30 minutos).
RF-05	E1 Acceso y cuentas	Sistema	El sistema deberá bloquear una cuenta durante 15 minutos tras 3 intentos consecutivos fallidos de inicio de sesión.	Como usuario, quiero que la cuenta se bloquee tras 3 intentos fallidos, para protegerla de adivinación de contraseñas.	Al tercer intento fallido se informa el bloqueo y el tiempo restante. El contador se reinicia con un acceso exitoso o al vencer el bloqueo. El administrador del sistema puede desbloquear la cuenta (RF-11).
RF-06	E1 Acceso y cuentas	Usuario (todos los roles)	El sistema deberá enviar al correo registrado un enlace de restablecimiento de contraseña cuando el usuario lo solicite.	Como usuario, quiero solicitar un enlace para recuperar mi contraseña, para volver a entrar si la olvidé.	El correo llega en menos de 2 minutos. La respuesta en pantalla es la misma exista o no el correo. El enlace es de un solo uso y tiene vigencia limitada y parametrizable en el archivo de configuración (por defecto 60 minutos).
RF-07	E1 Acceso y cuentas	Usuario (todos los roles)	El sistema deberá permitir al usuario definir una nueva contraseña desde un enlace de restablecimiento vigente.	Como usuario, quiero definir una nueva contraseña desde el enlace que recibí, para recuperar el acceso a mi cuenta.	La contraseña cumple la política (mínimo 8 caracteres, una mayúscula y un número). Un enlace usado o vencido se rechaza. Las sesiones anteriores quedan invalidadas.
RF-08	E1 Acceso y cuentas	Administrador del sistema	El sistema deberá permitir al administrador del sistema crear cuentas de Profesor, Auditor académico y Administrador del sistema y enviar al correo del usuario un enlace de activación.	Como administrador del sistema, quiero crear cuentas de usuario con su rol, para dar acceso a las personas autorizadas.	El correo institucional es único. La cuenta queda "pendiente de activación" hasta que se use el enlace (RF-09). Un profesor creado puede asignarse a cursos (RF-14).
RF-09	E1 Acceso y cuentas	Usuario (todos los roles)	El sistema deberá permitir al usuario activar su cuenta y definir su contraseña inicial desde el enlace de activación.	Como usuario, quiero activar mi cuenta y definir mi contraseña, para empezar a usar la plataforma sin que nadie conozca mi clave.	El enlace es de un solo uso y de vigencia parametrizable en el archivo de configuración. La contraseña cumple la política. Tras activar, la cuenta queda "activa".
RF-10	E1 Acceso y cuentas	Administrador del sistema	El sistema deberá permitir al administrador del sistema modificar el nombre, el correo y el rol de una cuenta.	Como administrador del sistema, quiero modificar los datos y el rol de una cuenta, para mantener actualizados los accesos.	Un cambio de rol aplica desde el siguiente inicio de sesión. No se puede quitar el rol al último administrador del sistema.
RF-11	E1 Acceso y cuentas	Administrador del sistema	El sistema deberá permitir al administrador del sistema activar, desactivar, bloquear y desbloquear cuentas de usuario.	Como administrador del sistema, quiero activar, desactivar, bloquear y desbloquear cuentas, para controlar quién puede entrar.	Una cuenta desactivada o bloqueada no inicia sesión y sus sesiones activas se cierran. Las cuentas no se eliminan, solo se desactivan.
RF-12	E1 Acceso y cuentas	Administrador del sistema	El sistema deberá permitir al administrador del sistema listar usuarios filtrando por rol y estado y buscar por nombre o correo.	Como administrador del sistema, quiero listar y buscar usuarios por rol, estado, nombre o correo, para encontrar rápido una cuenta para gestionarla.	El listado responde en menos de 2 segundos con hasta 200 cuentas. La búsqueda no distingue mayúsculas ni tildes.
RF-13	E2 Estructura académica	Auditor académico	El sistema deberá permitir al auditor académico registrar, modificar y consultar asignaturas con código, nombre, programa académico, créditos (3 o 4), horas semanales y nivel de la carrera (1 a 10).	Como auditor académico, quiero registrar y modificar las asignaturas con sus créditos y horas, para tener la estructura académica para calcular notas y asistencia.	El código es único. Los créditos solo admiten 3 o 4. "Asignatura" y "materia" son el mismo concepto. No se eliminan asignaturas que tengan cursos.
RF-14	E2 Estructura académica	Auditor académico	El sistema deberá permitir al auditor académico registrar y modificar los cursos de una asignatura en un período (por ejemplo T01 y T02) y asignar a cada curso un docente.	Como auditor académico, quiero crear los cursos de una asignatura y asignarles su docente, para saber quién dicta cada curso.	El código de curso es único por asignatura y período. Cada curso tiene un solo docente. Un docente puede tener varios cursos de una o varias asignaturas.
RF-15	E2 Estructura académica	Auditor académico	El sistema deberá permitir al auditor académico definir el horario semanal de un curso mediante uno o más bloques de día, hora de inicio y hora de fin (sesiones de 1, 2 o 3 horas).	Como auditor académico, quiero definir los días y horas en que se dicta cada curso, para calcular las horas totales y la inasistencia.	No se aceptan bloques que se solapen dentro del mismo curso. Cada bloque dura 1, 2 o 3 horas. Si la suma semanal difiere de las horas semanales de la asignatura se muestra una advertencia.
RF-16	E2 Estructura académica	Auditor académico	El sistema deberá permitir al auditor académico registrar períodos académicos (semestres) con identificador (por ejemplo 2026-2), fecha de inicio y fecha de fin de 16 semanas.	Como auditor académico, quiero registrar los períodos académicos, para conservar el histórico por semestre.	Solo un período puede estar "en curso". Se valida la duración de 16 semanas. Los períodos anteriores se conservan para consulta.
RF-17	E2 Estructura académica	Auditor académico	El sistema deberá permitir al auditor académico definir los 3 cortes de un período con su peso (30 %, 30 % y 40 %) y sus fechas de inicio, fin, límite de carga y límite de corrección.	Como auditor académico, quiero definir los cortes con sus pesos y fechas límite, para controlar los plazos de carga y corrección.	Los pesos suman 100 %. Las fechas son consecutivas y están dentro del período. El límite de corrección es posterior al de carga.
RF-18	E2 Estructura académica	Auditor académico	El sistema deberá permitir al auditor académico registrar los festivos de un período.	Como auditor académico, quiero registrar los festivos del semestre, para que las horas dictadas excluyan los días no hábiles.	La fecha es única por período y debe estar dentro de él. Un cambio de festivos avisa que se regenerarán los calendarios afectados (RF-19).
RF-19	E2 Estructura académica	Sistema	El sistema deberá generar para cada curso el calendario de sus sesiones a partir de su horario, las fechas del período y los festivos, y calcular las horas totales del curso en el período.	Como auditor académico, quiero que el sistema calcule las sesiones y horas totales de cada curso, para medir la inasistencia con una base correcta.	Un curso con 2 sesiones semanales de 2 horas en 16 semanas y sin festivos suma 64 horas. Una sesión que cae en festivo se omite. El calendario se regenera si cambian horario o festivos antes de registrar asistencia.
RF-20	E2 Estructura académica	Auditor académico	El sistema deberá permitir al auditor académico configurar los umbrales de alerta: nota de aprobación (3,0), límite de pérdida por inasistencia (30 %), umbral amarillo de inasistencia (20 %) y rango amarillo de nota (3,0 a 3,4).	Como auditor académico, quiero ajustar los umbrales de alerta sin tocar el código, para adaptar las alertas a las reglas académicas.	Los valores por defecto son los acordados. Cada cambio conserva histórico. Un cambio no recalcula las alertas de cortes ya cerrados.
RF-21	E3 Estudiantes e inscripciones	Auditor académico	El sistema deberá permitir al auditor académico registrar, modificar y consultar estudiantes con código, nombres, correo, programa y período de ingreso.	Como auditor académico, quiero registrar y modificar estudiantes, para tener la población sobre la cual calcular alertas.	El código es único. El período de ingreso define la cohorte. Los estudiantes no se eliminan; su situación se maneja con el estado (RF-22).
RF-22	E3 Estudiantes e inscripciones	Auditor académico	El sistema deberá permitir al auditor académico registrar el estado de un estudiante (activo, graduado, retirado formal, aplazó semestre o cancelado) con su fecha efectiva y conservar el historial de estados.	Como auditor académico, quiero registrar el estado de cada estudiante con su fecha, para distinguir graduados y aplazados de quienes no continúan.	No se permite inscribir en períodos posteriores a la fecha efectiva a un estudiante graduado, retirado o cancelado. El historial de estados es consultable.
RF-23	E3 Estudiantes e inscripciones	Auditor académico	El sistema deberá permitir al auditor académico inscribir y retirar estudiantes en cursos de un período, registrando el semestre de la carrera que cursan (1 a 10).	Como auditor académico, quiero inscribir estudiantes en cursos y registrar el semestre que cursan, para saber quién debe aparecer en cada curso.	Un estudiante no se inscribe dos veces en el mismo curso. Solo se inscriben estudiantes activos. El retiro de un curso conserva el historial.
RF-24	E3 Estudiantes e inscripciones	Auditor académico	El sistema deberá permitir al auditor académico cargar estudiantes y sus inscripciones desde un archivo CSV con validación previa, resumen de registros nuevos, actualizados y con error, y confirmación antes de guardar.	Como auditor académico, quiero cargar estudiantes e inscripciones desde un archivo, para evitar digitarlos uno por uno.	Archivo de hasta 5 MB con plantilla descargable. Las filas con error se informan con número y motivo. No se guarda nada hasta confirmar. La carga queda en la bitácora.
RF-25	E3 Estudiantes e inscripciones	Administrador del sistema	El sistema deberá incluir un procedimiento ejecutable por el administrador del sistema que genere datos coherentes de usuarios, asignaturas, cursos con horario, períodos, cortes, estudiantes, inscripciones, asistencia y notas de 4 semestres.	Como administrador del sistema, quiero generar datos de prueba y repetibles, para demostrar el prototipo sin usar datos reales.	Genera unos 900 estudiantes en total (unos 350 activos por semestre), 25 asignaturas, 50 cursos y 4 semestres (2025-1 a 2026-2). No usa datos reales. Puede borrarse y regenerarse.
RF-26	E4 Registro de asistencia y notas	Profesor	El sistema deberá mostrar al profesor los cursos que tiene asignados en el período en curso, con su horario y el estado de cada corte (pendiente, enviado o cerrado).	Como profesor, quiero ver mis cursos del semestre y el estado de cada corte, para saber qué debo cargar y hasta cuándo.	Solo se listan los cursos del profesor autenticado. El estado de cada corte coincide con RF-30, RF-36 y RF-37.
RF-27	E4 Registro de asistencia y notas	Profesor	El sistema deberá mostrar al profesor la lista de estudiantes inscritos en cada uno de sus cursos.	Como profesor, quiero ver la lista de estudiantes de mi curso, para registrar su asistencia y sus notas.	Solo para cursos propios. Muestra código y nombre, sin datos personales innecesarios.
RF-28	E4 Registro de asistencia y notas	Profesor	El sistema deberá permitir al profesor registrar la asistencia de una sesión de su curso marcando a los estudiantes ausentes; los demás se consideran presentes y a cada ausente se le cargan las horas de la sesión.	Como profesor, quiero marcar los estudiantes ausentes de cada sesión, para llevar la inasistencia sin hacerlo a mano.	Solo sesiones del curso ya dictadas y dentro del plazo del corte. Una ausencia en una sesión de 2 horas suma 2 horas. No se registran retardos. Tras el envío se corrige con RF-31.
RF-29	E4 Registro de asistencia y notas	Profesor	El sistema deberá permitir al profesor registrar la nota consolidada de cada estudiante inscrito en su curso para un corte, en escala de 1,0 a 5,0 con un decimal.	Como profesor, quiero registrar la nota de cada estudiante en cada corte, para que Bienestar detecte a quienes van perdiendo.	Se rechazan valores fuera de 1,0 a 5,0 o con más de un decimal. No permite registrar fuera del plazo de carga. Permite guardar un borrador antes de enviar (RF-30).
RF-30	E4 Registro de asistencia y notas	Profesor	El sistema deberá permitir al profesor enviar el registro de un curso para un corte únicamente cuando todos los estudiantes inscritos tienen nota y la asistencia está registrada hasta la fecha de fin del corte.	Como profesor, quiero enviar el registro de mi curso cuando esté completo, para que el auditor académico lo reciba y se calculen las alertas.	Si falta algún dato, el sistema lista lo pendiente y no envía. Al enviar, el curso queda "enviado" y se calculan las alertas (RF-43).
RF-31	E4 Registro de asistencia y notas	Profesor	El sistema deberá permitir al profesor corregir notas y asistencia de un curso ya enviado mientras no haya vencido el límite de corrección del corte, registrando un motivo obligatorio por cada corrección.	Como profesor, quiero corregir notas o asistencia después de enviar, con un motivo, para subsanar errores durante la socialización con los estudiantes.	Sin motivo no se guarda. Se conservan valor anterior y valor nuevo. Las alertas se recalculan. Pasado el límite solo es posible con reapertura excepcional (RF-38).
RF-32	E4 Registro de asistencia y notas	Sistema	El sistema deberá impedir cualquier modificación de notas o asistencia de un corte cerrado o vencido, salvo en los cursos con una reapertura excepcional vigente.	Como auditor académico, quiero que nadie modifique notas fuera de plazo, para garantizar la integridad de la información.	Un intento de edición fuera de plazo se rechaza con un mensaje. La información nunca se elimina, solo se modifica con historial.
RF-33	E4 Registro de asistencia y notas	Auditor académico	El sistema deberá permitir al auditor académico consultar el historial de cambios de notas y asistencia de un curso o de un estudiante: valor anterior, valor nuevo, motivo, usuario y fecha.	Como auditor académico, quiero consultar quién cambió qué y por qué, para revisar las correcciones realizadas.	Aparecen todas las correcciones de RF-31 y RF-38. Se puede filtrar por curso, estudiante y fechas.
RF-34	E4 Registro de asistencia y notas	Profesor	El sistema deberá mostrar al profesor, para cada estudiante de sus cursos, la nota acumulada, el porcentaje de inasistencia y el estado de alerta.	Como profesor, quiero ver cómo van mis estudiantes, para actuar a tiempo desde mi curso.	Solo estudiantes de sus cursos. Los valores coinciden con RF-40 a RF-43.
RF-35	E5 Cierre de cortes	Auditor académico	El sistema deberá mostrar al auditor académico, por corte, los cursos enviados y los pendientes con su profesor.	Como auditor académico, quiero ver qué cursos ya enviaron y cuáles faltan, para verificar que la información esté completa antes de cerrar.	Se actualiza al enviarse cada curso. Permite filtrar por pendientes.
RF-36	E5 Cierre de cortes	Auditor académico	El sistema deberá permitir al auditor académico cerrar un corte antes de su límite de corrección.	Como auditor académico, quiero cerrar un corte cuando la información esté lista, para impedir más cambios y consolidar las alertas.	Al cerrar, ningún profesor modifica ese corte. Los cursos no enviados quedan marcados "sin registro". Las alertas pasan de provisionales a definitivas.
RF-37	E5 Cierre de cortes	Sistema	El sistema deberá cerrar automáticamente un corte al vencer su límite de corrección.	Como auditor académico, quiero que el corte se cierre solo en la fecha límite, para no depender de que alguien lo recuerde.	La tarea programada corre una vez al día. Un corte vencido queda cerrado con la misma regla de RF-36.
RF-38	E5 Cierre de cortes	Auditor académico	El sistema deberá permitir al auditor académico reabrir un curso de un corte cerrado para su profesor por falla técnica, con motivo obligatorio y permitiendo únicamente modificar datos existentes.	Como auditor académico, quiero reabrir un curso por falla técnica, para permitir que el profesor corrija sin abrir todo el corte.	La reapertura es por curso y corte. No permite crear ni eliminar registros. Se informa el motivo y queda trazada.
RF-39	E5 Cierre de cortes	Auditor académico	El sistema deberá permitir al auditor académico cerrar manualmente una reapertura excepcional.	Como auditor académico, quiero cerrar una reapertura cuando el profesor termine, para volver a bloquear el curso.	La reapertura permanece vigente hasta que se cierre manualmente. Al cerrarla el curso vuelve a bloquearse y las alertas se recalculan.
RF-40	E6 Alertas y analítica	Sistema	El sistema deberá calcular la nota acumulada de cada estudiante en cada asignatura como la suma de las notas de corte multiplicadas por el peso de cada corte (30 %, 30 % y 40 %).	Como auditor académico, quiero ver la nota acumulada ponderada de cada asignatura, para conocer cómo va realmente el estudiante.	Con cortes 3,0, 2,0 y 4,0 la acumulada final es 3,1 (0,9 + 0,6 + 1,6). Con cortes parciales se muestra la acumulada parcial.
RF-41	E6 Alertas y analítica	Sistema	El sistema deberá calcular, tras cada corte, la nota mínima que el estudiante necesita en los cortes restantes para alcanzar una nota final de 3,0.	Como auditor académico, quiero saber qué nota necesita el estudiante para aprobar, para detectar a tiempo a quien ya no puede aprobar.	Tras el corte 1 con nota 2,0, la requerida es (3,0 − 0,3 × 2,0) / 0,7 = 3,43. Si la requerida supera 5,0 la asignatura se marca perdida por nota. Si es 1,0 o menos, aprobada.
RF-42	E6 Alertas y analítica	Sistema	El sistema deberá calcular por estudiante y curso la inasistencia acumulada (horas ausentes sobre horas totales del período) y el ritmo de inasistencia (horas ausentes sobre horas dictadas a la fecha).	Como auditor académico, quiero ver el porcentaje de inasistencia acumulado y su ritmo, para anticipar quién superará el 30 %.	Con 8 horas ausentes, 64 horas totales y 24 horas dictadas: acumulada 12,5 % y ritmo 33,3 %.
RF-43	E6 Alertas y analítica	Sistema	El sistema deberá determinar el estado de alerta (verde, amarilla o roja) de cada estudiante por asignatura y corte, indicando el motivo (nota, inasistencia o ambos), según los parámetros de RF-20.	Como auditor académico, quiero que el sistema clasifique a cada estudiante en verde, amarillo o rojo, para mapear quién está perdiendo o en riesgo durante cada corte.	Rojo: nota de corte menor que 3,0, o inasistencia acumulada mayor que 30 %, o nota requerida mayor que 5,0. Amarillo: nota de corte entre 3,0 y 3,4, o inasistencia acumulada de 20 % o más, o ritmo de inasistencia de 20 % o más. Verde en los demás casos. El estado es provisional con los datos disponibles y definitivo al cerrar el corte.
RF-44	E6 Alertas y analítica	Auditor académico	El sistema deberá permitir al auditor académico consultar la lista de estudiantes en alerta de un corte, filtrando por asignatura, curso, tipo de alerta, motivo y riesgo alto, mostrando el correo del estudiante.	Como auditor académico, quiero consultar la lista de estudiantes en alerta por corte, para contactarlos y apoyarlos.	Indica si el estado es provisional o definitivo. Ordena por severidad. Responde en menos de 2 segundos con unos 2.000 registros.
RF-45	E6 Alertas y analítica	Auditor académico	El sistema deberá permitir al auditor académico consultar el detalle de la alerta de un estudiante por asignatura: notas por corte, nota acumulada, nota requerida, horas ausentes, ritmo y porcentaje de inasistencia.	Como auditor académico, quiero ver el detalle de por qué un estudiante está en alerta, para orientar la conversación con él.	Los valores coinciden con RF-40 a RF-42. Muestra el motivo.
RF-46	E6 Alertas y analítica	Sistema	El sistema deberá marcar como "riesgo alto" a todo estudiante con estado amarillo o rojo en 2 o más asignaturas del mismo período.	Como auditor académico, quiero identificar a los estudiantes con varias asignaturas en alerta, para priorizar la atención.	El marcador se actualiza al recalcular alertas. Se puede filtrar en RF-44.
RF-47	E6 Alertas y analítica	Auditor académico	El sistema deberá permitir al auditor académico consultar el histórico de un estudiante por semestre: asignaturas, notas por corte, inasistencia, resultado y motivo de aprobación o pérdida.	Como auditor académico, quiero ver el histórico completo de un estudiante, para entender por qué aprobó o perdió cada asignatura.	Muestra los 4 semestres de datos de prueba. Indica aprobada o perdida y el motivo (nota, inasistencia o ambos).
RF-48	E6 Alertas y analítica	Auditor académico	El sistema deberá permitir al auditor académico consultar, por asignatura, curso y corte, el número de inscritos, aprobados, en alerta y perdidos y sus porcentajes.	Como auditor académico, quiero ver los resultados por asignatura y curso, para detectar asignaturas con más pérdida.	Los totales coinciden con la lista de alertas. Filtra por período, asignatura, curso y profesor.
RF-49	E7 Continuidad y deserción	Sistema	El sistema deberá determinar, para cada período, cuáles estudiantes inscritos se inscriben en el período siguiente y cuáles no, excluyendo a los graduados y a quienes aplazaron.	Como auditor académico, quiero saber cuántos estudiantes continúan de un semestre al siguiente, para medir la permanencia.	Un estudiante inscrito en 2026-1, sin inscripción en 2026-2 y sin estado graduado o aplazó, se clasifica "no continúa".
RF-50	E7 Continuidad y deserción	Sistema	El sistema deberá calcular el índice de no continuidad por período como los estudiantes que no continúan dividido entre los inscritos del período, excluyendo graduados y aplazados.	Como auditor académico, quiero ver el índice de no continuidad por semestre, para tomar decisiones sobre deserción.	Con 350 inscritos, 20 graduados, 5 aplazados y 30 que no continúan: 30 / (350 − 25) = 9,2 %.
RF-51	E7 Continuidad y deserción	Sistema	El sistema deberá calcular la no continuidad por cohorte de ingreso y por semestre de la carrera cursado (1 a 10).	Como auditor académico, quiero saber en qué semestre de la carrera se abandona más, para enfocar las acciones de permanencia.	Cada resultado puede reconstruirse a partir de RF-49.
